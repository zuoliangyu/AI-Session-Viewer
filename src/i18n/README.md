# 中英文界面

使用 `i18next` 和 `react-i18next`，在首屏渲染前同步加载本地词典。默认 `zh-CN`；用户在「设置 → 显示设置」中选择 `en` 后即时生效，偏好存放在 `localStorage["asv.language"]`。未知值、缺失值和存储不可用时回退中文，不读取系统语言。`document.documentElement.lang` 与当前语言一致。

## 添加文案

- `locales/zh-CN.json` 与 `locales/en.json` 使用相同键。当前以中文源文案作为键，关闭 `keySeparator` 和 `nsSeparator`，标点不会被解释为路径。
- React 组件调用 `const { t } = useTranslation()`，确保语言改变后重新渲染；普通函数从 `index.js` 导入 `t`。不要在模块初始化时调用 `t` 冻结翻译，静态配置的展示标签可使用 getter。
- 新文案应使用完整句子和具名占位符，例如 `t("跟随系统（{{zone}}）", { zone })`，不要依靠字符串拼接决定英文词序。历史迁移的模板使用 `v0`、`v1` 占位符；修改时可换成有意义的名称，并同步词典。
- `useMemo` / `useCallback` 中直接或间接生成翻译文案时，将组件的 `t` 放进依赖数组。不以语言作为组件 `key`，避免切换时丢失输入草稿、滚动位置或聊天流。
- 相对时间使用 `getDateLocale()`；紧凑数字使用 `getLanguage()`。语言不改变用户设置的时区，也不修改原始时间戳。
- 会话原文、用户名称/标签/路径、模型 ID、CLI 或服务器原始诊断不自动翻译。只翻译应用自己的界面文案。
- 语言菜单保留 `简体中文` / `English` 自称，方便用户找回语言。

## 验证

运行 `node scripts/check-i18n.mjs`，检查两套词典的键和占位符、初始化默认值、切换与持久化、存储异常回退、相对时间、JSX 语法与未抽取的中文界面文案。它不运行 TypeScript 类型检查或应用构建。

手动验收：打开设置，切换 English，检查导航、项目/会话、搜索、统计、聊天与弹窗，刷新后仍为英文，再切回中文；用户会话内容应保持不变。英文界面可用不等于满足 AppImage 目录“非中文系统默认英文”的收录要求，本项目当前明确默认中文。
